# URRC 몬자 대회 규정 및 제출 명세

대회 맵은 몬자 하나이며 예선과 본선에 동일한 world와 물리 설정을 사용합니다.

## 1. 제출 단위

팀별 `<entry_id>/` 폴더 하나 또는 동일 구조 ZIP 하나를 제출합니다. 폴더명, `race_entry.json`의 `entry_id`, Gazebo entity 이름은 같아야 합니다. ID는 영문자로 시작하는 1~32자의 영문·숫자·`_`·`-`만 허용합니다.

```text
team01/
  race_entry.json
  src/team01_race/
    package.xml
    CMakeLists.txt 또는 setup.py
    launch/race.launch.py
    models/race_car/model.sdf
    ...
```

운영자는 제출물을 `race/inbox/`에 넣고 `bash competition.sh prepare`를 실행합니다. 접수, `colcon build`, 계약 검사가 성공하면 폴더는 `race/entrants/`로 이동되고 ZIP은 `.loaded`로 바뀝니다. 같은 ID는 자동 덮어쓰기하지 않습니다.

## 2. 차량·센서 규정

- collision과 모든 돌출부 포함 최대 **1.20 m(L) × 0.50 m(W) × 0.35 m(H)**.
- 기준축은 `+X` 전방, `+Y` 좌측, `+Z` 위이며 원점은 차량 중심의 지면 투영점으로 합니다.
- 차량과 센서는 하나의 최상위 모델에 넣고 참가 launch에서는 spawn하지 않습니다.
- collision은 primitive/단순 convex를 권장합니다. 트랙 관통 형상, 비정상적으로 큰 invisible link는 금지합니다.
- LiDAR/거리 센서 1개 이상을 사용하며 센서도 최대 외형에 포함합니다.
- `spawn_z_offset_m` 기본값은 0.04 m, 권장 허용 범위는 0~0.15 m입니다.
- 운영자는 외형, 질량·관성, 접촉, 정지 드리프트, 센서 토픽을 검사하며 규격 초과 차량은 수정 전 출전할 수 없습니다.

## 3. ROS 2 계약

`vehicle_model_file`은 팀 폴더 기준 상대 경로입니다. launch는 다음 인자를 모두 받아 실제 노드에 전달해야 합니다: `race_start_topic`, `speed_topic`, `steering_topic`, `lidar_topic`, `use_sim_time`.

출발 토픽이 없거나 `false`이면 구동 명령은 0이어야 합니다. 참가 launch는 차량/world를 spawn·remove·실행하지 않습니다. 노드·토픽·service·action·TF frame은 팀 ID로 격리합니다. `/clock`, `/race/*`, `/world/*`에 참가 코드가 발행하거나 서비스를 호출하는 행위, 다른 팀 토픽 접근, 프로세스 종료, 파일 변경, 네트워크 통신, 관리자 권한 사용을 금지합니다.

## 4. 경기 방식

- 최대 12팀.
- 예선: 한 팀씩 1번 칸에서 2바퀴, 완주 시간 오름차순.
- 본선: 예선 순서대로 1~12번 칸에 배치하여 10바퀴 동시 주행.
- 빨간등 5개를 1초 간격으로 켜고 0.2~3.0초 뒤 소등하면서 출발 Bool을 보냅니다.
- 제한 시간: 예선 차량당 600초, 본선 2,400초.
- 완주자는 기록 순, DNF는 완주 랩 수 순입니다. 동률이면 마지막 유효 계측 시각, 그래도 같으면 예선 순위를 적용합니다.
- 최상위 모델 원점이 진행 방향으로 출발/결승 계측면의 도로 폭 안을 통과해야 랩을 인정합니다.

## 5. 스폰 기준

출발선은 `(0, 0, 1.22071)`, yaw `1.46663 rad`입니다. 예선/1번 칸은 `(x=0.37867, y=-2.05604, road_z=1.20353, yaw=1.45738)`이며 Z는 `road_z + spawn_z_offset_m`입니다. 전체 좌표의 기준은 `tracks/processed/monza.json`입니다.

## 6. 실격·재주행

- 출발 전 구동, 규격 초과, 중앙 시스템/타 팀 간섭, 코스 collision 변조: 해당 세션 실격.
- 고의 지름길, 벽 관통, physics 악용: 해당 세션 실격.
- 참가 코드 오류, 센서 설정 오류, 의존성 누락, 시간 초과: 재주행 없이 DNF.
- 중앙 실행기·Gazebo·전원·운영 장비 오류: 해당 주행을 무효로 하고 동일 설정에서 재주행.
- 일반 경주 접촉은 자동 재주행 사유가 아닙니다. 고의 방해는 로그와 영상으로 판정합니다.
- 규정 해석은 안전성과 동일 조건을 우선하며 같은 기준을 모든 팀에 공지합니다.

## 7. 제출 전 체크리스트

1. 깨끗한 ROS 2 Jazzy 환경에서 네트워크 없이 `colcon build` 성공.
2. `package.xml` 의존성 완전, 절대 경로 없음.
3. 외형·collision 규격 준수, 관성값이 0/음수/NaN이 아님.
4. 필수 launch 인자 5개 사용, 출발 전 정지.
5. 중복 spawn 없음, 팀별 이름 격리.
6. 지정 offset에서 바퀴 접촉과 정지 안정성 확인.
7. 몬자 2바퀴 연속 센서 주행 확인.
8. 제출 폴더 밖 파일·인터넷·사용자 홈 설정에 의존하지 않음.

운영자는 원본 제출 체크섬과 빌드 로그를 보관하고 예선부터 본선까지 소스·바이너리·환경을 변경하지 않습니다.
